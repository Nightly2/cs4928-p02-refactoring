### How the Implementation Supports the Requested Changes

1. **Step-by-Step Fluent Construction:**
The static nested `Builder` class allows constructing `Booking` instances incrementally via chained `with*` methods, terminating in `.build()`.
2. **Cohesive Parameter Grouping:**
The builder offers composite helper methods to group conceptually related domain attributes:
* `withDates(startDate, endDate)` groups temporal boundaries.
* `withCustomer(customerId, customerName, customerEmail)` groups customer identity profile attributes.
* `withDiscount(discountType, discountValue)` and `withTax(taxType, taxValue)` group pricing adjustment metadata.
*(Fine-grained individual setters remain available for flexible partial updates).*


3. **Full Backward Compatibility:**
The public 11-parameter constructor is retained with identical visibility and parameter order, preventing breaking changes in existing callers such as `BookingShould.java`.
4. **Preserved Logic & Immutability:**
All field types, immutability (`final`), and business logic within `statusFor(LocalDateTime date)` are unchanged.
